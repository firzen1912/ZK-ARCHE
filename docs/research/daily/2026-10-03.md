## 2. Executive synthesis

- Current ZK-ARCHE already specifies normal AUTH as NO-LEARNING and treats credential references, handles, cache keys, registry slots, and lookup hints as non-authoritative selectors. Multiple accepted paths must resolve to the same security object and attribution tuple or fail closed.
- Current LAKE implementation guidance distinguishes strict NO-LEARNING from deliberate exceptions where a new credential is only provisionally trusted until trusted authorization arrives later in the same session. This exposes a missing ZK-ARCHE research state between candidate credential retrieval/validation and durable ENROLL commit.
- LAKE also requires consistency when the same credential is supplied through ID_CRED and an EAD-carried envelope. Value/value, value/reference, and reference/reference paths must identify the same credential; inconsistency aborts the session.
- ELA requires an otherwise peer-local credential identifier to be unambiguous to a third-party enrollment server and requires the authenticator to use the same credential toward both the constrained peer and enrollment server. A future ZK-ARCHE cross-authority reference therefore needs explicit namespace/domain semantics and same-object continuity without making the reference itself security authority.
- EDHOC-PSK -09 permits one identifier to select multiple candidate PSK contexts but recommends unique or stochastic identifiers to reduce ambiguity/collision cost. ZK-ARCHE should keep semantic ambiguity fail-closed; lookup cardinality/CPU belongs to R-014 and observable timing/membership/linkability belongs to R-015.
- R-013 remains reproduce. No wire, suite/profile, code, spec, roadmap, CI, or trust-policy change is authorized.

### D20261003-F01 — Selectors are retrieval aids; accepted paths must converge on one canonical credential/attribution object

Current implementation guidance requires two accepted paths that carry/reference the same authentication credential to identify the same credential or abort. - Strongest distinct engineering idea: make the canonical credential/security object plus its locally authoritative attribution tuple the only security object; every identifier is a selector whose result must converge on that object before possession or authorization can be accepted.
- Evidence maturity: software
- Limitations / uncertainty: EDHOC formats/state machines are comparators, not ZK-ARCHE requirements. EDHOC-PSK permits multi-candidate retrieval while current ZK-ARCHE Common Contract semantics deliberately reject ambiguous mapping.
- ZK-ARCHE inference: R-013 no longer needs generic research on whether references should be authority. Remaining reproduction should target exact Rust/C parity for cross-path consistency, stale aliases, ambiguous mappings, context substitution, and lifecycle invalidation.

### D20261003-F02 — Authorized learning needs an attempt-scoped provisional trust state before durable promotion

- Novelty: new / refines
- Backlog owner: R-013 / R-008
- Sources/date/type: draft-ietf-lake-edhoc-impl-cons-07 and draft-ietf-lake-authz-08, both 6 July 2026 active LAKE WG I-Ds
- Primary links: https://datatracker.ietf.org/doc/html/draft-ietf-lake-edhoc-impl-cons-07 ; https://datatracker.ietf.org/doc/html/draft-ietf-lake-authz-08
- Verified claim: EDHOC implementation guidance distinguishes LEARNING, strict NO-LEARNING, and deliberate scenario-specific exceptions. In ELA's forward flow, a new credential received before the trusted enrollment-server voucher can at best be provisionally trusted; final trust follows successful voucher verification later in the same session.
- Existing engineering owner: R-013 / R-008 / zk211 / zk212 / TD-004
- Repository fact: ZK-ARCHE already has a hard NO-LEARNING normal-AUTH boundary and an ENROLL lifecycle separating authorization-to-issue from durable COMMITTED state, but no inspected surface names a provisional candidate-credential state between retrieval and final authorized promotion.
- Problem addressed: preventing a future authorized-learning exception from either mutating durable/global trust prematurely or reusing normal AUTH trust semantics.
- Strongest distinct engineering idea: research an explicit ENROLL-attempt-scoped provisional credential object. It may support the checks needed to obtain/verify trusted authorization, but is not globally trusted, cannot authorize parallel normal AUTH, and becomes durable only through the existing authorized lifecycle commit after same-object, authority, freshness, replay, lifecycle and rollback checks.
- Evidence maturity: concept
- Limitations / uncertainty: LAKE's storage model is not a ZK-ARCHE requirement. ZK-ARCHE could hold the candidate ephemerally or use a different staging abstraction. The required property is isolation of provisional candidate state from durable/global trust.
- ZK-ARCHE inference: R-013 should add provisional-state isolation and abort/timeout/restart behavior to its reproduction contract. Persisted staging, if ever used, must remain non-authoritative until the lifecycle proves a committed successor.
- Wire/CPU/RAM/flash/dependency/trust/privacy impact: no wire change needed to model the state; bounded RAM for ephemeral staging, with additional flash/recovery/rollback obligations only if staging is persisted. No new trust root.
- Rust/C/vector/profile impact: shared state cases should cover provisional creation, same-attempt authority confirmation, wrong/missing authority confirmation, credential mismatch on confirmation, concurrent normal AUTH, parallel enrollment, timeout/abort, restart before commit, and final promotion.
- Required next evidence: bounded wire-neutral state corpus/prototype proving provisional state cannot escape into normal AUTH or durable trust and composes with current ENROLL recovery.

## 6. Cross-source synthesis

The sources and repository support one decomposition: identifiers retrieve candidate state; authority comes from the credential/security object plus accepted local attribution/authorization. Multiple paths must converge on the same object. Deliberately authorized learning is a separate lifecycle operation whose provisional candidate state must not silently become ordinary trust before authorizing evidence and durable commit.

The residual R-013 question is therefore how explicit ENROLL/commissioner learning safely stages a candidate, proves that selectors and authority paths refer to the same credential/subject, and atomically promotes it without exposing provisional state to parallel AUTH, restart ambiguity, stale aliases, or rollback. Cross-authority lookup performance and observable privacy remain separate R-014/R-015 gates.
