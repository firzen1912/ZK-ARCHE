### D20261125-F01 — Calibrate analysis tools against labeled violations, not just a green DUT

- **Novelty / owner:** refines R-007, TD-001 (zk207/zk209), R-005 and R-015 cross-reference. September 25 already established compiler/backend provenance and statistical testing limits; November 6 established source witness-path asymmetry. Today's addition is a detector capability/ground-truth acceptance gate, not another generic recommendation to run dudect.
- **Primary source / date / type:** Lai, Zhang, Qiu, Pham and Parampalli, [A Quantitative Evaluation of Constant-Time Analysis Tools](https://eprint.iacr.org/2026/2682), IACR ePrint 2026/2682; received October 29, approved October 31, 2026; metadata lists ACSAC 2026 / minor revision. Checked November 25. [dudect author project](https://github.com/oreparaz/dudect), associated DATE 2017 paper, checked November 25.
- **Verified source-supported facts:** The authors' abstract describes AutoBench-CT, a benchmark with manually checked violation-level ground truth over 64 cryptographic tasks, compares seven tools on operational performance, detection quality and usability, and proposes combining analysis techniques. The dudect authors explicitly distinguish detecting statistical timing differences from proving their absence. The IACR PDF request returned HTTP 403; the full methods, tool list, metrics, dataset and comparative results were not verified. Do not infer specific tool superiority, sensitivity, or availability from the abstract.
- **Repository fact:** Both exact-head provers explicitly distinguish the true role index, use different real/simulated computation paths, and write true-index-dependent locations. Rust uses a witness-dependent search and draws one or two scalars by branch; C pre-draws the same total for a given n, then consumes branch-dependent segments. Existing deterministic vectors test correctness, not detection sensitivity. The formal auth skeleton abstracts the proof.
- **Bottleneck:** A negative statistical result can reflect insufficient detector sensitivity, an unexercised code path or invalid input partition. An aggregate tool count says nothing about per-feature observability.
- **Distinct engineering idea / ZK-ARCHE inference:** Use a local, labeled detection-control manifest before accepting an actual role-proof timing or trace experiment. Controls: public-only data-dependent branch (negative control for secret-label attribution), synthetic secret-dependent branch, synthetic secret-indexed memory read, and synthetic variable-work path, plus a fixed-work control. Record which detector sees which known property, actual public/secret labeling, compile/link settings, target, positive/negative outcomes and unsupported features. Keep a tool timeout or unsupported path as inconclusive, not a pass. Then use matched valid witness-class fixtures at the same public policy cardinality and separate RNG, arithmetic and whole-protocol observations; don't conflate changed public statements or invalid inputs with role leakage. A detector failure on its relevant positive control invalidates that detector's negative inference. Calibrate per target/toolchain, not just host. This is a proposed local methodology, not the paper's exact pipeline.
- **Evidence maturity:** software (author-reported benchmark abstract); concept (ZK-ARCHE gate). No detector or exact-head binary executed today.
- **Limitations:** Statistical non-detection cannot prove constant time; trace controls do not cover every microarchitectural, power/EM or network observer. Ground-truth controls must be reviewed in optimized code and synthetic data only; a physical role experiment still needs an independently reviewed fixture and sufficient samples. No inference of exploitability from source asymmetry.
- **Impact:** Wire/trust/dependencies unchanged; no runtime tool required. Host analysis CPU/disk/time and physical measurement effort increase; target runtime RAM/flash/CPU costs unchanged unless later instrumentation/mitigation is adopted. Privacy claim remains scoped and unqualified.
- **Rust/C/vector/profile:** Preserve suite 0x0001, deterministic DRBG order and current valid vectors. Same control manifest and acceptance semantics across Rust/C, compiler and architecture; separate synthetic control artifacts from normative wire corpus. No change to draft profile.
- **Required evidence:** Obtain full paper/artifacts; execute labeled positive/negative canaries and pinned local exact-head Rust/C optimized trace/timing runs, then target measurements; retain raw samples, artifact hashes, detector diagnostics and independently reviewed classification.

### D20261125-F02 — Specify deterministic input length and transactional output/secret ownership separately

- **Novelty / owner:** New exact-head API/header observation refining R-007 / TD-001; R-005 cross-reference. Builds on November 24 primitive zero/identity error behavior without asserting end-to-end reproduction.
- **Primary sources / dates / types:** Exact repository [C header](https://github.com/firzen1912/ZK-ARCHE/blob/36b2701a6de6c638928998acad9bf12453e05598/c/include/auth/proofs.h), [C implementation](https://github.com/firzen1912/ZK-ARCHE/blob/36b2701a6de6c638928998acad9bf12453e05598/c/src/crypto/proofs.c), [Rust implementation](https://github.com/firzen1912/ZK-ARCHE/blob/36b2701a6de6c638928998acad9bf12453e05598/rust/crates/proto/src/crypto.rs), [vector](https://github.com/firzen1912/ZK-ARCHE/blob/36b2701a6de6c638928998acad9bf12453e05598/rust/test-vectors/0x0001/role_set_membership.json), [Cargo.lock](https://github.com/firzen1912/ZK-ARCHE/blob/36b2701a6de6c638928998acad9bf12453e05598/rust/Cargo.lock) (exact-head source inspected November 25); [libsodium internals](https://doc.libsodium.org/internals) (living upstream docs, checked November 25; page showed update 12 days earlier, not proof of specific change date); [RustCrypto zeroize 1.8.2 docs](https://docs.rs/zeroize/1.8.2/zeroize/) (version-pinned library docs, checked November 25).
- **Verified source-supported facts:** The C header for auth_prove_role_set_membership_with_bytes first says 64*(n_roles+1), but later in that same comment specifies a minimum of 64*(2*n_roles-1). The actual function checks 64+128*(n-1), agrees with the latter and consumes data in role order. Its role-index search and Y computation precede branch-buffer memset; subsequent scalar multiplication failures can return after some branches have been written. Output count is assigned at successful completion only. The production wrapper wipes its own used randomness buffer after the deterministic function returns, including ordinary errors. The deterministic function accepts a const caller-owned input buffer. Its simulated ci/si are wiped after a successful simulated branch, while early multiply/subtract errors clear w_true and return before those wipes; actual stack/register retention is unmeasured. Rust prover uses local scalars/vectors and returns a Vec, with no explicit zeroization in that function; Cargo.lock pins zeroize 1.8.2, which alone establishes no call-site cleanup. Upstream zeroize documents limits for copies, reallocations and registers; libsodium likewise identifies application-side stack copies as outside its own routine's complete control.
- **Bottleneck:** Public deterministic callers can allocate the wrong length from the first header expression; successful-only vector checks do not specify whether a failed call leaves valid outputs, nor who owns erasure of private witness randomness. An error return alone is not a complete memory or output validity contract.

| n roles | first header expression (B) | implementation minimum (B) | first minus actual (B) |
|---:|---:|---:|---:|
| 1 | 128 | 64 | +64 |
| 2 | 192 | 192 | 0 |
| 3 | 256 | 320 | -64 |
| 4 | 320 | 448 | -128 |
| 8 | 576 | 960 | -384 |

These are direct integer calculations, not benchmark results. Existing ordinary vector behavior is not disproven. The actual function rejects too-short lengths before processing branch output, subject to its other earlier checks.

- **Distinct engineering idea:** Propose a failure-contract matrix at the primitive API and protocol ingress separately. Test the exact required size, one byte short, first-comment size and excess bytes for n=1/2/3/4/8 (bounded by compiled AUTH_MAX_ROLES); initialize branch/count outputs to known synthetic sentinels, force early and later arithmetic failures with synthetic inputs, and check that no failed proof is subsequently consumed, serialized or committed. Determine through human review whether outputs are explicitly invalid on failure or whether a transactional clear/count reset contract is required; do not assume the current header already promises one. Trace callers and ownership of caller-provided input, owned scratch, w_true and temporary scalar copies; examine normal/error paths and compiler-generated erasure with controlled test fixtures, not real credentials. For Rust, distinguish normal return, panic/unwind and panic-abort or reset; no universal destructor claim. Keep full AUTH failure-state evidence separate from raw API output behavior.
- **Evidence maturity:** software (exact source-level contract discrepancy); concept (fault/erasure test). No exact-head build, forced failure or memory capture executed today.
- **Limitations:** Partially written branches are not necessarily secrets or reachable from an untrusted network input; no actual stale-count consumption, secret recovery, exposure or remote exploit was demonstrated. Current callers may correctly ignore outputs on error. Optimizer/register/spill behavior, provider semantics and target memory clearing require measurement. The suggested upstream stack-zeroing API may be version/target dependent; no adoption recommended.
- **ZK-ARCHE inference:** A human-reviewed correction to the contradictory size comment could be compatible and independent from a behavioral decision about failed outputs. Avoid introducing a new nonce distribution, changing DRBG consumption, or relaxing the identity checks merely to remove an error return. Preserve NO-LEARNING and fail-closed authentication effect boundary.
- **Impact:** Wire and trust unchanged for documentation/test-only qualification. CPU/RAM/flash for any future scratch wiping/transactional buffers unknown; measure stack high-water, erasure cost and latency, with no mandatory dependency or new private state. Privacy benefit is potential reduction of local residue and role-sensitive failure behavior, not proved unlinkability.
- **Rust/C/vector/profile:** Add proposed cross-language deterministic consumption/failure cases, maintain successful suite 0x0001 vector bytes and role order. Document distinct typed errors vs panic behavior without silently normalizing them; no profile change.
- **Required next evidence:** Human review of API contract and caller effects; exact-head Rust/C sentinel/fault fixtures and successful byte parity, optimized-code erasure evidence on host and physical target, independent cryptographic and side-channel review; no modifications in this run.
