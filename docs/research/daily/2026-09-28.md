## 2. Executive synthesis

1. **An unlinkable credential proof is not a complete authorization or anti-theft mechanism.** JWP-BBS -03 binds a verifier-supplied `nonce` and `aud` into the presentation challenge and treats device/holder binding separately. Without device binding, possession of the issued credential is sufficient to derive presentations. ZK-ARCHE should preserve independent proof-validity, freshness, audience, holder/session-binding, and authorization predicates.
2. **Credential metadata can collapse the anonymity set even when the proof itself is unlinkable.** JWP-BBS treats clear Issuer Header variation, credential layout, `alg`, and device-binding type as privacy surfaces and uses fixed layouts plus decoys to normalize same-type credentials. R-015 should therefore include credential schema/layout/disclosure/predicate/algorithm/binding-class observability.
3. **The BBS core has a useful byte lower bound, but a complete presentation is larger.** BLS12-381 G1 points are 48 bytes and scalars 32 bytes. The BBS signature is 80 bytes; a core proof is `272 + 32*U` bytes for `U` undisclosed messages, before headers, disclosed payloads, commitments/sub-proofs, JSON/base64url framing, and transport overhead.
4. **Maturity remains insufficient for promotion.** JWP-BBS -03 is an individual Internet-Draft/candidate for JOSE work and defines no concrete sub-proof or device-binding algorithm. The BBS core -10 is currently expired/archived. R-002 remains `researching`.
5. **Research-provenance correction:** the 2026-08-17 report described Blind BBS and per-verifier-linkability extensions as expired. Datatracker now shows active -03 CFRG RG revisions dated 2026-06-26 and 2026-06-29. The historical report is preserved unchanged; today's report supersedes only that status statement.

### D20260928-F01 — Proof validity, freshness/audience, holder binding, and authorization are separate predicates

- **Novelty:** refines
- **Backlog owner:** R-002 / R-008
- **Source:** `draft-bormann-jwp-modular-bbs-03`
- **Primary link:** https://datatracker.ietf.org/doc/html/draft-bormann-jwp-modular-bbs-03
- **Source type / venue:** individual Internet-Draft, candidate for JOSE work; intended Standards Track
- **Publication date:** 2026-09-18
- **Verified claim:** the Presentation Header requires `nonce` and `aud`; its exact octets are bound into the core-proof challenge. Verification requires the verifier's transaction nonce and intended audience. Device binding is separate and optional; when absent the credential is not device-bound, and the security text states that possession of the issued form is enough to derive presentations. The draft's abstract permits device-key possession proofs without revealing the public key/signature, but concrete device-binding/sub-proof constructions are not defined.
- **Existing engineering owner:** R-008 / R-002
- **Repository fact:** ZK-ARCHE already separates authenticated session/security context from authorization context and requires authorization to remain audience/scope/validity/revocation/holder bound.
- **Problem addressed:** “valid anonymous proof” could otherwise be misinterpreted as fresh authorization by the intended device.
- **Strongest distinct engineering idea:** future acceptance should remain conjunctive: `credential_proof_valid && presentation_fresh && audience_matches && holder_or_session_binding_valid && authorization_current`.
- **Evidence maturity:** concept / work-in-progress standards design
- **Limitations / uncertainty:** not an IETF standard; concrete device-binding/sub-proof algorithms are absent.
- **ZK-ARCHE inference:** future vectors should include replayed presentation, wrong audience, fresh nonce with wrong holder/session, copied credential without holder binding, and valid proof with stale/revoked authorization.
- **Wire / CPU / RAM / flash / dependency / trust / privacy impact:** nonce/audience and holder-binding evidence add bytes/work; holder binding adds another proof/key dependency; no mandatory online service follows.
- **Rust/C / vector/profile compatibility impact:** any future optional profile needs deterministic accept/reject parity for nonce/audience/holder/authorization combinations; no current vector change is authorized.
- **Required next evidence:** concrete holder-binding algorithm, exact presentation binding fields, negative corpus, resource budget, authorization-lifecycle mapping.
- **Recommended disposition:** reproduce/research

### D20260928-F02 — Credential metadata is part of the anonymity set, not harmless framing

- **Novelty:** new/refines
- **Backlog owner:** R-015 / R-002
- **Sources:** JWP-BBS -03; BBS core -10
- **Primary links:** https://datatracker.ietf.org/doc/html/draft-bormann-jwp-modular-bbs-03 ; https://datatracker.ietf.org/doc/html/draft-irtf-cfrg-bbs-signatures-10
- **Source type / venue:** individual Internet-Draft plus IRTF CFRG draft
- **Verified claim:** JWP-BBS says the clear Issuer Header can narrow the anonymity set and recommends byte-identical headers, fixed claim layouts, and decoys across one credential type. It also warns that `alg` and device-binding type split the anonymity set. The BBS core privacy text independently says unlinkability applies to the proof value, while disclosed values, headers, network metadata, and side channels can still correlate presentations.
- **Existing engineering owner:** R-015 / `spec/privacy-considerations.md`
- **Repository fact:** R-015 already covers packet size, timing, error/retry, lookup, session/profile/capability visibility, but did not explicitly enumerate credential schema/layout/disclosure/sub-proof/algorithm/device-binding-class observability.
- **Problem addressed:** a rare schema, message-vector length, algorithm, predicate, or holder-binding class can identify a small population even if cryptographic proof values are unlinkable.
- **Strongest distinct engineering idea:** require a credential-observability budget: list stable/clear fields, estimate anonymity/cardinality impact, and normalize only where privacy benefit justifies bytes/CPU/RAM.
- **Evidence maturity:** concept
- **Limitations / uncertainty:** JWP fixed layouts/decoys are one design, not a ZK-ARCHE requirement; normalization itself costs wire/storage and can leak in other dimensions.
- **ZK-ARCHE inference:** R-015 should include credential type/schema, layout/message count, disclosed indices, predicate/sub-proof parameters, algorithm, and holder-binding class as first-class correlation surfaces.
- **Wire / CPU / RAM / flash / dependency / trust / privacy impact:** fixed layouts/decoys increase wire/storage but can improve anonymity-set consistency; sub-proofs/predicates add bytes and can fingerprint policy.
- **Rust/C / vector/profile compatibility impact:** future privacy corpora should compare semantically equivalent credentials across optional-claim patterns and verify intended observable shape.
- **Required next evidence:** observable-field/cardinality table; measured normalization cost; cross-verifier correlation experiment; residual-risk statement.

## 6. Cross-source synthesis

The safe comparison is not simply “BBS vs CDS.” A richer anonymous-credential path needs two independent gates:

```text
proof validity
+ presentation freshness / audience
+ holder or session binding
+ current authorization / revocation
= operation authorization

proof unlinkability
+ schema/layout/algorithm uniformity
+ disclosure/predicate minimization
+ transport/size/timing/failure privacy
= bounded end-to-end unlinkability claim
```

ZK-ARCHE's existing authentication/authorization/privacy separation is directionally correct. BBS remains an optional research profile until concrete implementation, whole-message, lifecycle, and target evidence exists.
