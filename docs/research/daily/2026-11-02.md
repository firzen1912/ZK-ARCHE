## 2. Executive synthesis

1. **Verified new upstream change:** Tamarin issue #881, opened July 7 and closed October 28, 2026, describes a case where proof output generated by `--prove --output` cannot be faithfully reloaded because substitutions and parsing normalize guarded conjuncts differently. The upstream fix PR #882 merged **October 28, 2026** (commit `4c658fcf6653832d60ebdeec1d4d1cab4d4470c1`), with dedicated regression models and tests. This changes how a future ZK-ARCHE Tamarin verification lane must qualify its retained proof artifacts; it does **not** establish a ZK-ARCHE model failure.
2. **Release/provenance matters:** Tamarin's latest tagged release visible at review time was `1.12.0`, published **March 7, 2026**, predating the October fix. Do not assert that v1.12.0 has or lacks the reported *behavior* without testing its exact release: the upstream issue concerns the evolving development code. A fixed development commit cannot silently be represented as stable v1.12 conformance.
3. **A separate output-format boundary:** PR #900 merged **October 6, 2026** (commit `795abf434dca1f167ea73f3603ebf625c7ae1972`) and enables `--output-json` for Tamarin diff-mode theories. The PR explicitly leaves `--with-json` in diff mode unsupported. A future privacy-equivalence evidence extractor must pin the exact binary and supported CLI mode rather than assume JSON output interchangeability.
4. **Repository boundary remains:** Existing retained ZK-ARCHE AUTH-v3/replay symbolic evidence is **ProVerif 2.05**, not Tamarin. Existing DATA and retained-authority ProVerif models do not yet establish ordered same-association invalidation through an effect frontier; Rust/C temporal classifier tests do not establish a complete emit/commit proof. No formal result was executed today.
5. **Decision:** Refine R-004's formal-output acceptance contract, preserve P0/`reproduce`, and require a local/exact-head canonical-model trial before choosing a Tamarin version or promoting formal claims. No roadmap or code change.

The merged patch normalizes stored formulas consistently, adds guarded-connective/existential-restriction tests, and refreshes analyzed regression artifacts. Add an upstream `UM_three_pass` or `guarded-connectives` reproduction on both the chosen release and fixed development commit to distinguish affected-version behavior before accepting/rejecting a tool build.
