### D20261114-F01 — A disclosed channel may disappear from the symbolic adversary's reach

- **Source/date/type:** Tamarin Prover primary upstream [issue #938](https://github.com/tamarin-prover/tamarin-prover/issues/938), reported **2026-09-15**, and [repair commit 6e93b8e](https://github.com/tamarin-prover/tamarin-prover/commit/6e93b8eb33b41bab0398e154876baf37d5d2d21e) dated **2026-11-08**; upstream bug report, source commit and regression tests.
- **Verified source claim:** The 1.12.0 reproducer `new c; let x=c in out(x); ... in(c,y)` gives a falsified attacker-injection exists-trace lemma and verified universal `only_ok` lemma despite disclosing `c`. Direct `out(c)` reverses those results correctly. The source analyzes secret channels before `let` substitution; aliased disclosures, embedded MSR and pattern contexts can lead to omitted attacker `In` rules. The proposed fix moves the analysis and adds three regression models.
- **Verified maturity/ancestry:** Upstream `develop` inspected **2026-11-14** at `03215cd03e7c844ca2be116b45aef9737db495fd`. GitHub comparison `6e93b8e...03215cd` is `diverged` (ahead 1, behind 1), so the proposed fix is **not on that branch's ancestry**. Issue #938 remained open. Source-level upstream software evidence; not a local ZK-ARCHE reproduction.
- **Owner/anchor:** R-004, TD-003, `rust/models/proverif/zk_arche_auth_v3_draft.pv`, `docs/assurance/assurance-and-validation.md`; R-015 privacy only cross-reference.
- **Bottleneck:** Erased attacker behavior can make bad authorization/secrecy traces unreachable and a universal lemma vacuously true.
- **Distinct engineering idea:** Execute exact pinned Tamarin 1.12.0, reviewed development HEAD and explicit repair revision against the *three* upstream regressions and direct-channel control. Require adversarial injection **reachable**, intentionally false universal safety lemma **falsified**, and translated MSR `In` rules present. Retain model SHA, binary/git/Maude versions, warnings, transformed theory, exit codes, positive and negative results.
- **Evidence maturity/limitations:** `software` upstream; `concept` ZK-ARCHE applicability. No current Tamarin model or local canary execution; reported issue and branch ancestry are not proof of a production exploit or full implementation fix.
- **ZK-ARCHE inference:** Before modeling aliases or relayed authority in SAPIC, explicitly prove that the symbolic adversary can exploit all public channels. Do not promote symbolic privacy/security claims until translation is semantically qualified.
- **Wire/CPU/RAM/flash/dependency/trust/privacy:** **No current device or wire impact.** Future development-only Tamarin/Maude runtime/CPU/RAM and pinned dependency cost; trust and privacy risk lies in false model confidence, not new deployed metadata.
- **Rust/C/vectors/profile:** `0x0001`, Rust/C wire and deterministic vectors untouched. Any runtime adversarial ingress/authority trace is future human-reviewed model-to-code work.

### D20261114-F02 — Typed macro binders silently capture independent arguments

- **Source/date/type:** Tamarin primary upstream [issue #944](https://github.com/tamarin-prover/tamarin-prover/issues/944), reported **2026-09-15**, and [repair commit c867d9c](https://github.com/tamarin-prover/tamarin-prover/commit/c867d9cc87d3908c55b95cbb457c5e3c67129b66) dated **2026-11-12**; upstream bug report/source change.
- **Verified source claim:** For `let P(x)=in(y:bitstring); event A(x,y)` then `in(y); P(y)`, affected 1.12.0 silently emits `A(y.2,y.2)` rather than two independently bound variables. The exists-trace query for `A('a','b')` is falsely unreachable. The repair introduces scope-aware capture avoidance and regression coverage for nested calls, patterns, typed binders and embedded rules.
- **Verified maturity/ancestry:** On **2026-11-14**, comparison `c867d9c...03215cd` returned `behind`, ahead 0, behind 4: the November 12 patch **is an ancestor of examined develop**, but issue #944 remained open and tagged 1.12.0 predates it. Ancestry does not replace local executable proof of correct translation.
- **Owner/anchor:** R-004, TD-003, `spec/authorization-generation-lifecycle.md`, symbolic AUTH-v3 model. Exact security concern is unintended equality of subjects/keys/audiences/generations in future formal encodings; no present `.spthy` file.
- **Bottleneck/distinct engineering idea:** Require alpha-renaming metamorphic equivalence and paired positive/negative tests: original versus distinct inner/outer names; typed vs untyped binders; direct/nested process calls; embedded-MSR scopes; deliberate false equality lemmas. Inspect generated `A` events and reject accidental identifier capture or unexplained well-formedness warnings. Pin original and patched tool revisions, Maude, translation outputs, model hashes.
- **Evidence maturity/limitations:** `software` upstream candidate repair; `concept` ZK-ARCHE relevance. No local execution or evidence that the existing ProVerif model is affected; neither issue status nor branch ancestry proves runtime security.
- **ZK-ARCHE inference:** Maintain independent identities, generation values, sessions and authorization provenance in future synchronized formal backends; a successful proof with collapsed variables is not an authorization proof.
- **Wire/CPU/RAM/flash/dependency/trust/privacy:** No protocol/device overhead; development-only formal-tool CPU/RAM and artifact storage. Model-level trust/identity confusion is the risk; no measured network privacy impact.
- **Rust/C/vectors/profile:** No Rust/C/`0x0001`/vector change. Future explicit human review can map distinct-identity failures into matched Rust/C negative tests.
