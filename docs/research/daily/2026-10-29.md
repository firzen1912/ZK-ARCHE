## 2. Executive synthesis

1. **Shared device does not imply shared authority.** Google's Matter fabric primer describes multiple independent security fabrics and operational credentials coexisting on one physical device, while some network and application state is shared. This supplies a concrete multi-authority adversarial comparator for ZK-ARCHE local credential attribution and DATA authorization, beyond the same-serial collision examined October 18.
2. **Post-commit behavior needs a separate oracle from precommit rollback.** The official connectedhomeip network commissioning test (file last changed 2026-10-16) deliberately sends `ArmFailSafe(expiryLengthSeconds=0)` *after* successful `CommissioningComplete`, expecting it not to undo committed network state. This is a test pattern, not a proof of ZK-ARCHE trust-store durability.
3. Retain R-013 as P0/`reproduce` and refine its evidence contract to include domain-qualified object attribution, cross-domain authorization noninterference, and an explicit durable commit frontier. No protocol field or mandatory PKI/Matter dependency is proposed.
4. No Rust/C code was executed, no physical power-loss/flash tests performed, and no new ZK-ARCHE security property proved today. All research recommendations remain subject to human review.

## 5. Findings

### D20261029-F01 — Independent authority domains can share a physical device without sharing authorization

- **Novelty:** refines the 2026-10-18 R-013 issuer-collision concern with a concrete same-device/multiple-authority and shared-data-surface noninterference question.
- **Backlog owner / engineering owner:** R-013; R-008 holds directional and audience-bound authorization; zk211/zk212/zk239, TD-004 are human-reviewed downstream owners.
- **Source / primary link:** Google Home Developers, *The Fabric*, official implementation-ecosystem technical primer, last updated **2022-07-13**: https://developers.home.google.com/matter/primer/fabric .
- **Verified source-supported claim:** Matter's independent fabrics can coexist on a device, with distinct operational credentials and security domains. The node data model and network configuration may nonetheless be shared between fabrics. Its Fabric ID is scoped to the owning root-of-trust namespace; independent administrators are not interchangeable.
- **Repository facts:** `spec/implementation-requirements.md` §4.1 requires a single authoritative attribution of credential/reference/key/peer/role/audience and forbids implicit equivalence when a key appears under multiple local records. `spec/p2p-local-trust-and-delegation.md` states local trust is nontransitive; grant and DATA authorization decisions remain separately gated. The inspected Rust/C iot-core tests cover classifier/record mismatch but are not an end-to-end two-authority shared-device storage test.
- **Bottleneck addressed:** A physically shared device and reused opaque label could accidentally collapse two *authorization* namespaces, including when an alias/cache path resolves correctly cryptographically but under the wrong owner or policy.
- **Distinct engineering idea / ZK-ARCHE inference:** Build a local two-authority **shared-object noninterference matrix**: authority A and B provision one device with the same display/opaque label but different authenticated issuer roots/issuer handles and rights; both may authenticate within their own scope, but an A-key/alias/cache lookup never authorizes B's role, DATA view, revocation, replacement or delegation. Add cases where the physical DATA resource is shared but per-authority policy diverges and where one authority revokes its grant while the other remains valid; deliberately permitted cross-domain delegation must be an explicit separately authorized artifact.
- **Evidence maturity:** comparator documentation is official ecosystem guidance; ZK-ARCHE hypothesis is **concept**. No newly executed Rust/C differential corpus, formal proof or deployed privacy evaluation.
- **Limitations:** Matter operational credentials, X.509 roots/fabrics, and shared network-config semantics are not ZK-ARCHE's mandatory certificate-free Common Contract. The example does not establish that ZK-ARCHE currently conflates domains or needs a new on-wire authority identifier.
- **Likely impact (wire / CPU / RAM / flash / dependency / trust / privacy):** no mandatory wire change; local domain-qualified mapping may use bounded CPU/RAM and additional persistent namespace metadata depending on profile; storage costs require counting before adoption. No Matter/CA/cloud dependency. Explicit per-domain policy improves authority isolation; cross-domain persistent aliases or visible namespace tags could add linkability and require R-015 analysis.
- **Rust/C / vector / profile compatibility:** preserve existing positive fixtures and core profile wire format; require equal Rust/C decisions for A-only, B-only, ambiguous, aliased, stale, changed-role, changed-generation and legitimately delegated cases. A future namespace representation needs human-selected canonical byte and profile ownership.
- **Required next evidence:** implement-independent test table with actual credential/reference bytes, paired issuer/authority identities, per-authority generation and policy epochs, allowed versus denied DATA operations, local alias/cache invalidation, stale generation, and no-learn-on-AUTH or reject-on-ambiguity expectations; then local exact-HEAD Rust/C vectors and property-based tests.
- **Recommended disposition:** reproduce; **weekly finding candidate:** yes.

### D20261029-F02 — Commit frontier must distinguish reversible staging from durable success

- **Novelty:** refines R-013's provisional/committed barrier through a specific official test pattern for post-completion non-rollback, not merely a generic recommendation to handle interruption.
- **Backlog owner / engineering owner:** R-013; zk211–zk213, TD-002/TD-003 and R-004 (formal state sequencing) are independent downstream evidence owners.
- **Source / primary link:** Matter-connected implementation, `project-chip/connectedhomeip`, `src/python_testing/TC_CNET_4_9.py`, last file-change commit **2026-10-16**, SHA `2308c1a9b3bf8a626559b5dfe3eb2bfe1b89a8e0`: https://github.com/project-chip/connectedhomeip/blob/2308c1a9b3bf8a626559b5dfe3eb2bfe1b89a8e0/src/python_testing/TC_CNET_4_9.py . Supporting official primer, **2022-07-13**: https://developers.home.google.com/matter/primer/commissioning .
- **Verified source-supported claim:** The official test calls `CommissioningComplete`, checks success, then calls `ArmFailSafe(expiryLengthSeconds=0)` with an explicit test comment that it should have no effect after correct completion/persistence, and checks the resulting network list. The primer describes arming a fail-safe for commissioning rollback and disarming it at completion.
- **Repository facts:** `spec/enroll-lifecycle-state-machine.md` distinguishes `ISSUANCE_AUTHORIZED`, `COMMITTING`, `COMMITTED` and `RECOVERY_REQUIRED` and forbids successor trust becoming usable while the operation identifier may still recover unused. `spec/lifecycle-persistence-freshness.md` requires an atomic or recoverable multi-component security-state transition. The inspected `rust/crates/proto/src/enrollment_grant.rs` and `c/src/proto/enrollment_grant.c` are decision classifiers, not proof of persistent trust/alias/operation-ID commit ordering.
- **Bottleneck addressed:** A test suite checking only that aborted onboarding is rolled back can miss an inverse bug: expiration or cleanup after confirmed commit revokes valid trust, or an interrupted commit leaves a usable credential with a reusable enrollment nonce.
- **Distinct engineering idea / ZK-ARCHE inference:** Specify a **four-cell commit-frontier matrix** for the same enrollment attempt: (1) precommit abort/timeout -> no ordinary AUTH access and old trust retained; (2) crash after staging alias but before committed credential/nonce -> no new trust on restart, or fail-closed recovery; (3) complete durable commit -> successor usable and operation identifier consumed; (4) postcommit fail-safe expiry/duplicate completion -> never roll back the valid committed successor or reauthorize a consumed operation identifier. Cross with parallel same-nonce attempts and policy/revocation-generation changes during committing.
- **Evidence maturity:** **software** for the external Matter test pattern; **concept** for ZK-ARCHE transaction model. No ZK-ARCHE crash-cut implementation or physical flash verification was performed.
- **Limitations:** the cited test primarily checks Matter network-commissioning rollback/persistence, not enrollment credential+alias+nonce transaction durability; therefore its coverage must not be extrapolated to cryptographic trust storage, nor equated with ZK-ARCHE's no-clock replay continuity.
- **Likely impact (wire / CPU / RAM / flash / dependency / trust / privacy):** proposed test-only work has zero wire change, no new dependency. A future durable journal/recovery design may cost flash writes, retention space, CPU and bounded RAM; those costs require STM32/ESP32-S3 measurements. Trust impact is stronger commit/restart isolation; privacy impact includes avoiding externally distinguishable postcommit retry and rollback-oracle behavior.
- **Rust/C / vector / profile compatibility:** add identical outcome-class fixtures and scheduler/power-cut manifests to both lanes, pin commit-before-visibility semantics, test same operation ID and alias mapping through abort/restart/duplicate-after-commit; keep `iot-core`/P2P profile promotion disabled until storage evidence exists.
- **Required next evidence:** local exact-HEAD deterministic classifier/state-machine vectors, a two-phase or atomic-commit storage adapter test with injected cuts before/after every durable write, no-clock and rollback-suspected cases, followed by physical power-loss/flash-wear measurements and a stateful temporal model showing non-vacuous pre-allow/deny sequences.
- **Recommended disposition:** reproduce; **weekly finding candidate:** yes.

## 6. Cross-source synthesis

These sources are comparators, not imported specifications. The official multi-fabric model exposes a **domain noninterference** test even when the hardware and DATA store are physically shared; the current Matter commissioning test supplies a **commit/no-rollback** postcondition to complement ZK-ARCHE's already-specified abort/recovery rules. The novel joint question is whether both properties hold simultaneously for the exact local trust tuple (credential, alias, issuer-domain, authorization generation, policy, revocation view, used operation identifier), not whether Matter uses a better credential format. The October 18 issuer-collision and provisional-state findings remain valid, but neither supplies this complete two-authority shared-object plus postcommit oracle.
